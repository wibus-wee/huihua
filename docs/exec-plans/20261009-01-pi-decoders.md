# Additive JSONL decoders and configurable Pi providers

## Purpose / Big Picture

Consumers can teach Huihua about extension-owned records without replacing a provider or
postprocessing only read().
All replay APIs use the same decoder integration, while original records and builtin mapping
remain intact.
The default Pi provider remains compatible with existing fixtures and v1 goldens.

## Surprises & Discoveries

Metadata patches cannot retract previously published singleton facts.
Decoder parent-session candidates must therefore wait for EOF before canonical publication.
Scan-known creation time changes the native metadata prefix in open() compared with acquired
stream(); tests compare decoder contributions without incorrectly requiring identical acquisition metadata.
Original JSONL text includes its physical newline and is passed unchanged under output selection.
The ExecPlan skill's references/PLANS.md resource could not be read through either the alias or
the full package URI; this plan follows the required sections listed in the available SKILL.md.

## Decision Log

- Shared JSONL ingestion owns execution; provider factories own configuration.
  Replacing read() alone misses parse(), stream(), open() and selective delivery.
- Use create() with a closure per replay, following per-run rule creation in ESLint.
  A generic state parameter complicates heterogeneous decoder lists without adding capability.
- Native records are shared by reference under a read-only contract.
  There is no deep freeze, cloning or sandbox.
- Preserve builtin events and unknown fallback; contributions append in configured order.
  Decoders never claim a record or replace the native mapper.
- Core assigns event envelopes and provenance, namespaces metadata, and arbitrates parent IDs.
  It does not expose Ingestion to decoders or accept arbitrary Session patches.
- No new infrastructure dependency is needed: existing JSONL acquisition and synchronous callbacks
  already supply framing, backpressure and cleanup.
  Unified and Rollup transform pipelines would permit source replacement and add unrelated machinery.

## Context and Orientation

src/shared/ingestion.ts owns jsonlProvider() and its ingestLines() replay loop.
It is used by file-backed read/open/select/consume and acquired parse/stream.
src/providers/pi/index.ts currently exports one assembled provider.
src/ingest/index.ts exposes provider-authoring helpers.
src/contracts/decoder.ts defines callbacks and three contribution kinds: event, metadata and
an explicit parent-session candidate.
RawRecord.sequence is physical read order; each contribution references a RawRecord from its replay.

## Validation and Acceptance

Default provider results remain identical.
Configured decoder runs preserve original evidence and builtin events; contributed events carry
core-assigned sequence, record reference and decoder provenance.
Concurrent/repeated replays do not share private state.
Selection matches full-stream filtering and does not change decoder inputs.
EOF contributions can reference earlier records; errors, cancellation and early return do not
invoke finish() and close the producer.
Conflicting parent candidates remain inspectable and cannot silently establish canonical lineage.
Native lineage has precedence, including a native fact arriving after a decoder candidate.
Installed JavaScript and TypeScript consumers can configure Pi without importing the builtin root.

## Idempotence and Recovery

All acquisition is read-only.
Replay callbacks are recreated for each invocation and failed replays are discarded.
No source, dependency lockfile or golden requires migration.

## Interfaces and Dependencies

SessionDecoder has id and create({ provider, source }).
create() returns decode(input) and optional finish(); both return contribution arrays.
Inputs distinguish valid records from malformed gaps.
Each contribution carries its original RawRecord; core validates replay ownership.
Metadata is published under metadata.decoders[id]; each namespace retains its latest metadata
snapshot and all parent-session candidates with evidence record numbers.
Event envelopes add providerMetadata.decoder, and contributed tool IDs use a decoder-specific scope.
Existing SessionProvider and agent-session/v1 remain unchanged; new fields are optional metadata.
