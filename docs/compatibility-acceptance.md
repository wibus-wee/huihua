# Agent Sessions compatibility acceptance

The confirmed findings in the [comparison audit](../plans/agent-sessions-compatibility-audit.md) are implemented in the existing TypeScript readers and Usage consumer.
Acceptance checks source discovery, decoded native facts, tool identities/errors, accounting scope and complete evidence preservation; successful compilation is only a separate packaging check.
The reference is pinned to Agent Sessions `6fa9a73f489d37f655873871e5e6a5cf6975d1ff`.
Official facts, third-party observations and implementation decisions remain separated in each provider's RESEARCH.md.

## Regression proof

The 27 added cases live in the existing [provider harness](../tests/provider-imports.test.ts), [behavior harness](../tests/behavior.test.ts), [SQLite harness](../tests/sqlite.test.ts) and [Usage harness](../tests/usage.test.ts).
Replaying the new tests and immutable captures against a disposable archive of pre-fix `a2dc624` gives 26 failures and one passing negative control (no context leak where attribution did not yet exist).
Focused reproductions were established before each implementation change; malformed-context and quoted-DDL/media boundaries additionally failed against the intermediate implementation before their corrections.
The four complete harnesses then pass all 194 cases.
Updated negative controls also pass: a native Qwen functionResponse suppresses the display fallback, and malformed Codex records clear model context.

No static v1 golden, generated fixture database or dependency lockfile was edited.
The 12 added reference artifacts are byte-for-byte copies with pinned commit/path/SHA-256 entries in [fixture provenance](../fixtures/compatibility/README.md).
The existing hash checker verifies all 34 independent artifacts.
Native temporary SQLite databases provide independent DDL/row evidence; production readers remain pure TypeScript and read-only.

## Validation commands

```sh
node --test tests/provider-imports.test.ts tests/behavior.test.ts tests/sqlite.test.ts tests/usage.test.ts
pnpm check
node packages/usage/dist/cli.js --provider kimi --provider codex --timezone Asia/Singapore --json
node packages/usage/dist/cli.js --provider opencode --timezone Asia/Singapore --json
```

The full package check includes lint, strict types, dependency/layer policy, fixture/golden compatibility, resource/streaming behavior and installed package validation.
On 2026-10-08, pnpm check passed all 409 tests, lint, strict types, Knip, executable architecture policy and installed ESM verification (65 files), using pinned pnpm 12.4.2 on macOS / Node 26.10.0.
The Codex serialization regression found during full validation was corrected in implementation; unchanged native same-record facts retain the original metadata and immutable baselines pass.
These checks supplement the behavior and native-counter comparisons above.
