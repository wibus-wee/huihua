# Huihua v0.4.0

This release adds provider-authoring helpers, optional selective session reading,
and broader native-store coverage.

## Added

- `huihua/ingest`: a provider-authoring kit exposing the existing bounded ingestion
  helpers, JSONL framing, JSON/SQLite store factories and discovery utilities.
- `huihua/registry`: compose a custom registry without loading builtin providers.
- `millisOf(timestamp)`: convert native timestamps to epoch milliseconds; absent
  or unparseable timestamps remain absent.
- Optional `OpenSession.select()` and `consume()` capabilities for selective frame
  and callback delivery.
  Claude and Codex also expose `consumeUsage()` and
  `consumeUsageFacts()` through their existing parsers.
  Diagnostics and source
  validation remain active.
- Cursor chat and ACP `store.db` support for the confirmed persisted text graph.
  Repeated references retain repeated events; private variants and unreferenced
  blobs remain native evidence.
- Claude Desktop/Cowork discovery and combined environment, conventional and XDG
  roots.
  Kimi file-backed sessions expose native agent identity and role metadata.
- A private `@huihua/usage` workspace CLI for daily token totals and model
  breakdowns, with date/timezone filters, text/JSON output and opt-in
  `--workers 2|4`.
  It is an example consumer, not a separately published package.

## Fixed

- Certify Qwen, Claude, Cursor and historical OpenCode directory candidates using
  bounded native metadata checks, reducing false-positive session discovery.
  Explicit file inputs remain available for portable evidence acquisition.
- Fall back to conventional Qwen roots when configured projects are missing or
  are not a directory; an existing empty configured directory remains authoritative.
- Group events by record in the registry's read-only SPI fallback instead of
  rescanning every event for each record.

## Compatibility

The session schema remains `agent-session/v1`.
Existing full reads preserve
complete records, source order, repeated IDs and unknown data.
New reading
capabilities are optional; check member presence on the handle.

Directory scans may now omit unrelated or uncertifiable files previously returned
as sessions.
Provider coverage remains evidence-backed and does not certify every
private format or product release.

The private Usage CLI emits `huihua-usage/v2`, replacing its unreleased
observation-only v1 output.
It rejects discovery failures rather than reporting
incomplete coverage as complete totals.
Missing counters remain unavailable and
uncertain totals are labeled partial.

APIs remain under active development and may change between releases.
