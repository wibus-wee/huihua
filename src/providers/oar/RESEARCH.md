# OAR recording compatibility evidence

Reviewed upstream at `9ca3162b0ea7a937ae8230cabd8967ec3855c5d2` on 2026-10-05.

| Official facts                                                                                                                                                                                                                                                 | Third-party compatibility experience                                                | Huihua decisions                                                                                                                                                                                             |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| [Voyage writer](https://github.com/botiverse/oar/blob/9ca3162b0ea7a937ae8230cabd8967ec3855c5d2/packages/oar/src/voyage.ts) defines `oar-voyage/3`: header, wrapped record, end. Missing end means a truncated capture.                                         | No separate exporter format was verified.                                           | Accept voyage/3 and unwrapped RawEvent JSONL from CLI `--json` or `session.records()`. Other voyage versions are retained and diagnosed; no speculative migration. No default export directory.              |
| [Record contracts](https://github.com/botiverse/oar/blob/9ca3162b0ea7a937ae8230cabd8967ec3855c5d2/packages/oar/src/contracts/records.ts) distinguish frame, request and response. Frames include full native payload and ordered projected events.             | Existing Huihua native providers are independent readers, not OAR runtime adapters. | Keep each complete export line as one RawRecord. Interpret the recorded `body.events`; do not reparse native payload through another provider or emit its projection twice.                                  |
| `sessionId`, `agentPath`, `spanId`, `seq` and `receivedAt` attribute records; call identity includes the agent path. Observation time is epoch milliseconds.                                                                                                   | Bare call IDs collide between agents.                                               | Preserve these fields in event metadata; canonical sequence remains physical read order. Scope missing-result diagnostics by native session and agent path.                                                  |
| Prompt/steer/queue are request facts; user_message is a separate runtime observation. Text deltas and tool progress are not assembled results.                                                                                                                 | Deduplicating request and echo loses delivery evidence.                             | Keep both, label requests, retain chunks and repeated IDs. Progress is system evidence; only tool_call_ended becomes a result. Requested model/effort stays header metadata, not a reported assistant model. |
| [Runtime composition](https://github.com/botiverse/oar/blob/9ca3162b0ea7a937ae8230cabd8967ec3855c5d2/packages/oar/src/index.ts) includes Claude, Codex, Grok, Kimi, Antigravity and Pi; Cursor is supplied separately. Community Morph is included by its CLI. | A runtime connection does not establish its disk schema.                            | The OAR provider reads recordings from any runtime, including custom ones. Native stores have independent providers and evidence boundaries; recording support does not certify every harness-private store. |

Fixtures are synthetic schema examples.
Unknown projected events and frames with no interpreted events remain unknown evidence.
Task updates and ends remain system facts unless the individual record establishes agent identity; no task-history fold is used to guess subagent relationships. `isError` means an explicit `failed` result was recorded; absent outcome is retained in the complete result object.
